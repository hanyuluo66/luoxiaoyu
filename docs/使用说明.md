# 落小鱼 · 微信 AI 自动回复机器人

一个单文件 Windows 程序：把你电脑上登录的微信接给大模型（默认 DeepSeek），
私聊、群聊自动回复，所有规则都在一个本地网页控制台里配置。

- 界面：单 exe，双击运行 → 系统托盘常驻 → 自动打开浏览器控制台（只监听 `127.0.0.1`）
- 回复：私聊 / 群聊分别开关，群聊支持「仅@我 / 关键词 / 全部消息」三种触发
- 监听：白名单/黑名单、关键词规则、固定话术、AI 人设、免打扰时段、频率限制、人工接管
- 模型：OpenAI 兼容协议，内置 DeepSeek / OpenAI / 硅基流动 / Kimi / 通义预设

---

## 一、先决条件

程序对 **微信 4.1.12+ 已实测通过**（本机验证版本 **4.1.15.53**），**不需要降级**。

运行要求：
- Windows 10 / 11
- 微信 **4.1.12 或更新**，**已登录且窗口保持打开**（可以最小化）
- 一个模型 API Key（默认 DeepSeek，到 <https://platform.deepseek.com> 申请）
- 程序需要读取微信进程内存：**不要**给它打上「低完整性」标签，
  也不要放在被系统限制的目录里（详见 [`微信版本说明.md`](docs/微信版本说明.md)）

> 技术原理速览：微信 4.x 界面是自绘的，但它内部有一个 Qt 无障碍「闸门字节」，
> 写成 1 后控件树立刻可读；程序读消息走**本地数据库解密**、发消息走
> **UIA 控件 + 回车**，全程不注入代码、不需要 OCR。

## 二、快速开始

1. 双击 `落小鱼.exe`。首次启动会在 exe 同目录生成 `data\` 文件夹。
2. 浏览器自动打开控制台（端口 8760，被占用会顺延）。
3. 进「**AI 接口**」：选 DeepSeek，填 API Key，点「测试连接」确认能通，再点「保存并生效」。
4. 进「**私聊设置**」：把要自动回复的好友加进名单（可以点「从微信拉取会话」直接选）。
5. 进「**群聊设置**」：把要回复的群加进名单，触发方式建议先用「仅@我」。
6. 回「**概览**」确认微信连接正常、监听会话数不为 0，然后点「启动」。
7. 让朋友发条消息试试，回「**消息日志**」能看到收到/回复/跳过原因。

> 第一次建议先用「系统设置 → 接入模式 → 模拟模式」熟悉界面和调人设：
> 模拟模式不连微信，也不会真发消息，可以直接注入假消息看效果。

## 三、控制台页面

| 页面 | 作用 |
|---|---|
| 概览 | 运行状态、微信连接、今日统计、实时动态 |
| 私聊设置 | 私聊开关、白名单/黑名单、是否要关键词 |
| 群聊设置 | 群聊开关、名单、触发方式（@我/关键词/全部） |
| 监听规则 | 关键词/正则/固定话术/静默，按优先级匹配 |
| AI 接口 | 模型、Key、人设 Prompt、温度、上下文轮数、测试连接、试跑 |
| 收发节奏 | 回复延迟、冷却、每分钟上限、免打扰、人工接管、永久忽略 |
| 消息日志 | 每条收到/回复/跳过及原因 |
| 系统设置 | 接入模式、手动发消息、注入测试消息、数据目录 |

## 四、后台运行与「不抢鼠标」

程序在系统托盘常驻，发消息默认走**静默模式**：

- **鼠标完全不动**（发送全程不移动光标）
- **不会最小化你的任何窗口**
- 打字期间微信会短暂到最前（约 2~3 秒），发完立刻把你原来的窗口还回来
- 需要时可用环境变量 `DAFEIYU_SILENT=0` 退回旧的「点击式」发送

> 为什么不能完全不抢焦点：Windows 的键盘输入只送给**当前前台窗口**。
> 只要用模拟键盘（回车发送）就必须让它短暂到最前。真正的零打扰只有
> 官方 API 路线（企业微信）能做到，但那样管不到个人微信好友。
## 五、规则怎么排优先级

一条消息的处理顺序是固定的：

1. 总开关 → 会话黑名单 → 发送人黑名单 → 忽略关键词
2. 私聊/群聊开关 → 该会话是否在监听范围
3. **监听规则**（按 `优先级` 数字从小到大，命中即停）
4. 都没命中时看默认：私聊默认回复；群聊按「触发方式」决定

所以：想让某个群「只有提到某词才回」，用法是给这个群建一条范围=群聊、会话=该群、
匹配=包含、关键词=那个词、动作=AI 的规则，然后把群聊触发方式设为「关键词」。

规则支持占位符（固定话术里用）：`{msg}` 对方原话、`{sender}` 发送人、`{chat}` 会话名、
`{time}` 当前时间、`{nickname}` 机器人昵称。

## 六、常见问题

**微信连接显示失败**
- 确认微信是 3.9.11.17；4.x 一定会失败。
- 确认微信已登录、窗口没关。程序需要微信窗口存在（可以最小化）。
- 看 `data\logs\app.log` 的最后几行。

**能收到消息但不回复**
- 「消息日志」里会写明跳过原因：不在名单、冷却中、免打扰、频率上限、人工接管、规则忽略等。
- 群聊默认只在被 @ 时回复，检查群聊触发方式。

**我手动回了消息，机器人就不吭声了**
- 这是「人工接管」：你手动发言后，该会话自动暂停 N 分钟（默认 10，可在「收发节奏」改）。
- 想立刻恢复：概览/收发节奏页的「正在人工接管」列表点「恢复」。

**微信群聊里 @ 我没有被识别**
- 机器人靠「@ + 自己的微信昵称」判断。昵称里有特殊字符时可能漏判，
  此时把群聊触发方式改成「关键词」更稳。

**程序会被封号吗？**
- 本程序用 UI 自动化模拟人工点击输入，不注入、不破解协议，风险低于 Hook 方案。
- 但任何微信自动化都违反《微信个人账号使用规范》，长期高频自动回复仍有被限制的可能。
  建议：只回复必要的会话、控制频率、开冷却、别做营销群发。

## 七、目录结构

```
落小鱼.exe        主程序
data/config.json    全部配置（控制台保存的就是它）
data/bot.sqlite3    消息与事件日志
data/logs/app.log   运行日志
```

备份就是复制整个 `data` 文件夹。

## 八、从源码运行 / 重新打包

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install --no-deps .\vendor   # 内置的 wxauto 3.9
.\.venv\Scripts\python.exe main.py                            # 开发运行（托盘 + 浏览器）
.\.venv\Scripts\python.exe tools\run_dev.py --mock            # 只跑控制台，模拟模式
.\.venv\Scripts\python.exe tools\selftest.py                  # 后端自测（32 项）
.\.venv\Scripts\python.exe build.py                           # 打包 dist\落小鱼.exe
.\.venv\Scripts\python.exe build.py --console                  # 诊断版（带控制台输出）
```

> 注意：`vendor/wxauto` 是源码母本，**必须用普通安装**（不要 `-e`），
> 否则 PyInstaller 不会把 wxauto 打进 exe。改了 vendor 里的代码后要重新装一次。

技术栈：Python 3.14 + FastAPI + SQLite + 原生 JS 控制台；
微信操作基于内置的 wxauto 3.9（`vendor/wxauto`，UI 自动化，不注入）。

## 九、退出与自启

- 关闭窗口**不会**退出程序，它在系统托盘常驻。
- 退出方式：托盘图标右键 → 退出；或网页侧边栏底部的「**退出程序**」按钮。
- 开机自启：把 `落小鱼.exe` 的快捷方式放进
  `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`。
